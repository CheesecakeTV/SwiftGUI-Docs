# sg.PythonConsole
The `sg.PythonConsole` lets you integrate the actual Python-console into your layout.

That means, `print` and `input` can be used, even if the console is not visible.

# Basic functionality
When creating a window that contains an `sg.PythonConsole`, standard input/output streams are overwritten.

Now, every time you use `print`, it is output to the `sg.PythonConsole`, IN ADDITION to the "real" console.
Ideally, both should have the same text at all times.

When using `input(...)`, a popup opens.
The user may input their text and press return.
The entered text is displayed in a different color in the `sg.PythonConsole` element.

There is also the option to reroute warnings/errors (everything that is shown in red text on the console) to the element.
However, you need to enable it by setting the option `reroute_stderr = True` when creating the element.
Error-text is displayed in a different color too, default is red.

# Default event
There is no default event, since it is not intended for the user to change the text.

# Value
The value of `sg.PythonConsole` is all the text inside the element, same as with `sg.TextField`.

It can be overwritten, but should only be done in order to clear it (`my_console.set_value('')`)

## json
`to_json` returns `None`, so the value is not saved, countrary to the normal `sg.TextField`.

`from_json` does nothing either.

# Options
The element is derived from `sg.TextField`, so most of its options and methods work the same.

This tutorial only covers options different from `sg.TextField`.

## reroute_stdout
If True, print(...) will "print" to this element now.

## reroute_stderr
If True, warnings and exceptions are printed on this element now.
    
## reroute_stdin:
If True, input() will cause a popup to open and ask for an input-text.

## Colors
- `input_text_color`: Color of the text generated by a user-input (usually green/lime)
- `error_text_color`: Color of the text generated by an error (usually red)

# Methods
## write
Write something to the element like `print` would do.

The text is written to the "real" console aswell.

## write_error
Write something to the element like warnings/errors would (red color).

The text is written to the "real" console in red color aswell.

## write_input
Write something to the element like user-inputs would do (green color by default).
As with user-entries, a newline-character is added in the end.

The user is NOT prompted to enter a text, it's a pure write-operation.

The text is written to the "real" console aswell.

# Tips
You can make separate `sg.PythonConsole` elements for normal outputs and errors.
Just set `reroute_stdout = False` and `reroute_stdin = False` for the error console.

Having multiple `sg.PythonConsole` elements at the same time can cause issues, if they reroute the same stream.
Theoretically, `stdout` and `stderr` should work on multiple elements simultaniously, but `stdin` definetly does not.

However, there will be issues if the created elements are not destroyed in the opposite order of their creation.
If you can make sure this is never the case, there should be no issue with consoles rerouting the same stream.
